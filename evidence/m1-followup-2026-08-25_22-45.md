## What node 1760 contains

The summary is the [Session Arc Summary] that the system injected at the top of THIS conversation — the structured ~6KB message that began the session with "Active Project / Current task 1 activity / Current Evidence and Decisions / Remaining Work / Historical Task Snapshot".

This is a depth-0 leaf summarization, NOT a parent batch compression. The LCM tried to summarize a single ~21K-token input by sending it to Qwen2.5-0.5B at n_ctx=4096 — which is physically impossible regardless of timeout.

## What this means for M1

**M1 is not invalidated.** M1 addresses parent-batch-compression timeouts (the original 648-node failure mode). Node 1760 is a different failure mode: a single-call summarization against a model that cannot fit the input. M1 cannot solve this and was never designed to.

**A separate fix is needed.** Candidates:
- (a) `LCM_SUMMARY_MAX_INPUT_TOKENS` guard at the LCM summarizer entry point — refuse to call when input exceeds budget; degrade gracefully (truncate or split).
- (b) Route large single-call summaries to a larger-context model (no such model currently runs on this host — only Qwen2.5-0.5B and Qwen2.5-1.5B-ish via llama-server).
- (c) Pre-truncate input to LCM_LEAF_CHUNK_TOKENS chunks and stitch — fragile, may produce incoherent summaries.

The parent's "failure was capacity, not latency" diagnosis from the original 3-model audit was correct. M1 addressed the latency-shaped manifestation of that diagnosis; the capacity-shaped manifestation remains.

## Policy compliance note (added during this analysis)

The M1 env patch set `LCM_SUMMARY_TIMEOUT_MS=90000` in `~/.config/hermes-gateway.env`. Per `projects/hermes-agent/AGENTS.md`:

> New HERMES_* env vars for non-secret config. .env is for secrets only. All behavioral settings — timeouts, thresholds, feature flags, display prefs — go in config.yaml.

However, hermes-lcm code reads `auxiliary.compression.timeout` from `config.yaml` FIRST (`hermes-lcm/config.py:266-278`), then falls back to env. The policy-compliant M1 edit would have been `auxiliary.compression.timeout: 90` in YAML. Live config.yaml already has `auxiliary.compression.model` at line 111 (Edit 3 fix) but not `auxiliary.compression.timeout`. **The env patch is functionally correct but policy-inconsistent.** Captured in proposed ADR-2026-08-25-07.
